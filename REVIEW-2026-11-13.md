- **STORE-5 step 3** — let `mutate` derive widget reloads from a "what widgets draw" projection and delete the `reloadWidgets:` parameter (36 call sites decide by hand). Guard with a test walking `WidgetContent`'s inputs.

- **APP-11** — `send()` still rewrites the index and snapshot and prunes media on the main actor as the composer dismisses; `CrashReporter` parses JSON synchronously at launch; audio session activation on main.
- **CLOUD-10** — a status change is two sequential saves (three on a stale cache). One non-atomic `modifyRecords` for status + log.
- **CLOUD-11 / APP-12** — captions have no rejected backoff; missing favourites retry forever (now bounded, but still every pass); receipts marked abandoned even offline; the owner's share check runs every cold launch and hourly after the link is closed; the account cache expires every 5 min in the app; a Siri heart triggers a full refresh; archive and recap fetch one record per moment (batch them).

## Overcomplicated — redesign candidates

1. **Announcement model (STORE-7).** One question — which partner moments has nobody announced? — is answered by an id ring, a legacy id, a time floor on the sender's clock, four claim paths, `bannerCandidates`, `isNews` three times and a "stuck floor reads as now" rule restated five times. Replace with an owed queue: the fold appends news ids to `Snapshot.unannouncedMoments` (as `removalNotices` already works); announcing takes the queue in one `mutate`; upkeep asks "is it empty?". Port `PushBannerPolicyTests`/`AnnouncementPolicyTests` as the spec.
2. **Re-entrancy gates (CLOUD-12, APP-9).** ~20 hand-rolled `guard !flag; flag = true; defer` with three hidden semantics (drop, re-run once, join). One `Exclusive`/awaited gate type where each loop names its policy; `isBusy` → `pairingOperation: PairingOperation?`. One `RetryPacing` for throttle, storage-full, status backoff and rejected uploads.
3. **Split `AppModel` (APP-10, redesign C).** Move gates/readiness/path monitor/catch-up/recovery into a testable `SyncCoordinator` in `Shared/`; an `InviteLinkModel`; an `ArchiveModel`. Make `SyncRunner` an instance.
4. **Unreadable records (CLOUD-4)** and **batched app resync (CLOUD-3)** — above.
5. **Archive as a stream (redesign A, APP-1's rest).** Chunks of ~25, batch-fetched with `desiredKeys` = the one asset straight into staging, failures classified (transient / gone / unsupported), `gone` listed for explicit confirmation.
6. **Test seam under `CloudSync` (CLOUD-13).** A narrow `CloudDatabase` protocol `CKDatabase` conforms to, with stores injected as `Outbox` does; start with `refresh` and `unpair`.
7. **View decisions out of views (UI-6).** `HomeView.activeNotice`, `SyncFooter`'s precedence, `SettingsView.saveMemories/end` (the destructive gate), gallery `settle`, the status draft rules, `consumePendingRoute` → pure types in `Shared` with table tests.
8. **Duplicate UI (UI-7).** Four report dialogs, two identical caption fields, two Save-to-Photos routines, three hand-styled capsules.
