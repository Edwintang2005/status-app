# Red String — agent guide

Two-person iCloud status app (iOS 17+, SwiftUI). One partner sets a status/nudge/photo/doodle/voice memo; it appears on the other's lock screen. No server: everything travels through CloudKit (a zone-wide `CKShare`), human-readable fields end-to-end encrypted via `encryptedValues`. Three shipping targets (app, widget extension, notification service extension) plus a unit-test bundle — all compile `Sources/Shared/`.

`README.md` is the deep reference (design rationale, pairing/share security model, shipping/CloudKit-schema steps, demo mode). Read the relevant README section before changing sync, pairing, or notification behaviour. `ROADMAP.md` lists planned features. This file is the quick map + the invariants that must not break.

Comment style: comments are deliberately lean — one or two lines carrying only the non-obvious constraint or "why". Don't add narrative comments, restate code, or document history; match the existing density.

## Build & run

- `RedString.xcodeproj` is **generated** from `project.yml` by XcodeGen (`make project`) but also **committed** (Xcode Cloud needs it). After adding/renaming files: `make project`, commit the regenerated project too. Never edit project settings in Xcode's UI — they're overwritten.
- `make build` = unsigned compile check (do not launch the product). CI (`.github/workflows/ci.yml`) runs the xcodegen drift check (pinned version), the unit tests and unsigned Debug + Release builds with warnings as errors; strict concurrency is `complete` (Swift 5 mode), so keep every target at zero warnings. `static.yml` deploys only `docs/**`. `make run` = signed build + launch in Simulator. `make device`, `make archive` per README.
- Demo mode for screenshots/UI work: launch with `REDSTRING_DEMO=1` (Debug only) — stub backend + `DemoSeeder` content, no iCloud needed.
- `make test` runs `Tests/RedStringTests` (XCTest). The bundle compiles `Sources/Shared/` directly — no host app, so no signing or App Group — and covers the persistence invariants below: Codable fallbacks, watermarks, `MomentIndex`/`StatusHistoryLog` merging, `SharedStore`, plus the pure decision types the CloudKit code delegates to — `RefreshDelta` (how a delta folds into `Snapshot`), `AnnouncementPolicy` (every notification's check-and-claim) and `WidgetReloadPolicy` (the widget's next refresh), `ParsedDelta` (how `CloudSync.apply` sorts and judges a delta: unreadable holds, reported moments, deletions by role, new vs own writes — with real `CKRecord` fixtures), `Outbox` (every offline-send loop against `FakeBackend`: republishes, pending uploads, the full-iCloud back-off, the receipt claim), `ZoneGonePolicy`, `RefreshGate`, `MediaPrefetchPlan` (what each process downloads after a refresh), `ZoneClearPlan` (which own records an unlink or a fresh start deletes), `FreshStartPolicy` (the fresh start's record transitions, commit detection, each phone's next step, the zone plan and the local purge — plus a two-phone handshake simulation: withdraw-vs-commit, both asking, a stale agreement), the fresh start's ingestion (`FreshStartIngestTests`: the epoch filter, authorship, caps) and its `Outbox` loop (`FreshStartOutboxTests`), `ArchiveContents` (the archive's zone + local merge), and `GroupFileStore`/`CrossProcessLock` on a temporary directory (migration, sidecars, two-lock contention) — and smaller pure helpers (`withDeadline`, `confirmSaved`, `SendFailure`, moderation, anniversary maths, moods, `PairRole`, waveforms) and ingestion (`IngestTests`: `TrustedTime`, the record parsers' caps). Stores take an injected file URL, directory or `UserDefaults` suite; never touch the real container from a test — and note the host-less bundle *does* resolve the simulator's real App Group container (the simulator doesn't check the entitlement), so a `.shared` singleton in a test writes the installed app's data. `MomentIndex`/`StatusHistoryLog` keep their lock file beside their data file, so a test's lives in its temp directory; `SharedStore`'s static locks still resolve the container (lock files only). Keep decisions in those types: `CloudSync.apply` only performs what `ParsedDelta` decided, and `AppModel` hands the send loops to `Outbox` (injected store, index, backend and upload protection); `SyncRunner` and the NSE still have no coverage.
- User-facing text is localisable: SwiftUI `Text` literals and `String(localized:)` for everything else (notification bodies, widget strings, accessibility labels). Each target owns a `Resources/Localizable.xcstrings`; an Xcode IDE build fills it (xcodebuild leaves it empty, which is harmless — keys are the English strings). Every icon-only control carries an `accessibilityLabel`; `Theme.rounded` follows Dynamic Type (capped at 1.35×).

## Architecture (data flow)

```
UI (Views/) → AppModel (@MainActor, @Observable)
            → Backend.current (SyncBackend protocol: CloudSync actor, or DemoBackend)
            → CloudKit custom zone "CoupleZone", zone-wide CKShare

SharedStore (App Group, file-backed KV via GroupFileStore)  ← app / widget / NSE all read+write
  ├─ Snapshot        widget-renderable cache: both statuses, nudge watermarks, latest moments
  ├─ PairingInfo     role (owner/participant) + zone coords + account userRecordName
  └─ change tokens   per-database CKServerChangeToken

MomentIndex   moments-index.json in App Group — full history metadata (cap 500)
MomentStore   media files in App Group /Moments — JPEG full (photo's own frame) + square thumb, .m4a (full media capped to the 60 newest, thumbnails kept for the whole index;
              pending-upload media is never pruned)
StatusHistoryLog  status-history.json — local rolling log of both sides' statuses (cap 300: both sides' `statusLogLimit` of 150)
SyncRunner    refresh → decide what to announce → NotificationManager (local notifications)
NotificationService  enriches CloudKit pushes: refreshes, decrypts, rewrites banner, reloads widgets
```

Key types: `FreshStart` (one per side, `freshstart-<role>`: encrypted `stage`/`epoch`/`clearedBefore` — the fresh start handshake and the lasting mark of what was cleared; no subscription), `StatusPayload` (one per partner, fixed record names `status-owner`/`status-participant`), `StatusLog` (one record per status change, `statuslog-<role>-<seconds>`, the durable history; each side prunes its own past `AppConfig.statusLogLimit`), `Nudge` (own record type so its push can be visible+sound), `Moment` (one record per item, name `moment-<role>-<uuid>`, kept forever — that's what makes history recoverable), `Receipt` (one per side, `receipt-<role>`: encrypted seen-map plus the status read receipt (`statusSeenAt`/`statusSeenFor`), no subscription — arrives with any refresh), `Anniversary` (one per pair, fixed name `anniversary`, owner-written: encrypted `startsAt` + `timeZone`, the clock behind the easter egg; no subscription), `AnniversaryRequest` (one per pair, fixed name `anniversary-request`, participant-written: encrypted `requestedAt` — "please set the date"; no subscription, the owner sees it on their next open). `PairRole` derives all per-side record names; neither device ever needs the other's CloudKit user ID.

## Invariants — do not break

1. **Cross-process locking.** App, widget, and NSE run concurrently on the same triggers. Every read-modify-write of `Snapshot` goes through `SharedStore.mutate` (flock-based `CrossProcessLock`); `MomentIndex` locks likewise. Check-and-claim decisions (announce a nudge/moment, rewrite a banner) must happen *inside* one `mutate`.
2. **Apply before token, and readable before token; media after both.** `CloudSync.refresh` folds records into local state *before* persisting the change token. Reversing it loses records forever when the NSE is killed on deadline. Asset downloads (`prefetchMedia`, executing `MediaPrefetchPlan`) run only *after* the token is written and never in `apply` — no record depends on its media, and a download inside `apply` held the NSE's banner and token behind a backlog of photos. A record whose encrypted fields come back empty (`CloudSync.isReadable`, probed on a field every version has always written) is skipped, listed in `RefreshResult.unreadableRecordNames`, and the token is *not* advanced — a background process without the share's keys must not consume a delta it couldn't read, or the words are gone for good. The per-process tally shows in Diagnostics. The one exception is the *app with protected data available* giving up (`SharedStore.protectedDataAvailable`, kept current by `AppDelegate` from the protected-data notifications — a locked phone's background refresh has no keys either): `SharedStore.noteUnreadableRecords` counts separate app refreshes (≥ `AppConfig.unreadableHoldSpacing` apart) that skipped the same record names, and after `AppConfig.unreadableHoldLimit` of them returns `true` so the token advances — otherwise one record nobody can ever read pins the token and the whole delta behind it forever. Extensions only add to the tally; they never advance. Unreadable never means absent: `MomentIndex.insert` keeps held captions/names/waveforms over empty ones, `logEntry(from:)` writes no placeholder, and `RefreshDelta` clears the anniversary or status receipt only on an explicit deletion / a readable receipt.
3. **Shared state lives in files, not UserDefaults.** `UserDefaults(suiteName:)` proved unreliable as an App Group channel (see `GroupState.swift`). Widget↔app data goes through `GroupFileStore` / files.
4. **Encryption boundaries.** Text and behavioural fields (`emoji`, `message`, `displayName`, `caption`, `senderName`, `waveform`, `isCelebration`, the receipt's `seenMap`/`statusSeenAt`/`statusSeenFor`, the anniversary's `startsAt`/`timeZone`, the request's `requestedAt`) go through `record.encryptedValues`. Plaintext by design: record names, moment `kind`/`sentAt`/`duration`/`momentID`, nudge `count`/`sentAt`, `updatedAt` — the locked-phone banner depends on `kind` staying readable. `CKAsset`s are encrypted by CloudKit automatically and must NOT go through `encryptedValues`. Adding a plaintext field that carries user words is a privacy regression.
5. **Hand-written Codable.** `Snapshot`, `StatusPayload`, `Moment` decode with `decodeIfPresent` + fallbacks so old on-disk data survives new fields. New persisted fields must follow that pattern (and consider what the fallback means for legacy data).
6. **Widgets reload via `SharedStore.reloadWidgets()`** after any snapshot/media change — but never from inside the widget process (guarded by `isRunningInWidgetExtension`).
7. **Cooldown claims before network.** `CloudSync.sendNudge` claims the cooldown inside the lock before the network call; a failure releases it and stamps `lastNudgeFailedAt` (the lock-screen heart's only error channel).
8. **Unlink is cloud-first.** `unpair()` must succeed before local state is cleared; `forceLocalReset` is the explicit escape hatch. "Zone gone" under a *different* iCloud account must never wipe local state (`SyncError.differentAccount`). **"Zone gone" is a verdict only on a second sighting** (`CloudSync.zoneGoneVerdict`): the first stamps `SharedStore.zoneGoneSeenAt` and throws the transient `SyncError.zoneUnreachable`; only a sighting `AppConfig.zoneGoneConfirmation` later wipes and throws `linkEnded`, and any successful fetch clears the stamp. The invite-close handshake takes the partner off the share for seconds, and one refresh in that window must not cost them their unsent media. When the verdict does land, `eraseLocalMedia(keepingPendingUploads: true)` spares own sends that never reached CloudKit, `clearPairing(keepingName: true)` remembers the zone in `SharedStore.lastPairing`, and `acceptShare`/`rejoin` (via `adoptPairing`) skip the wipe when the accepted zone is that same one — so the re-tapped link re-sends them. A different zone, a new invite, or "start over" still wipes. A new invite never reuses a zone with someone on its share or any records in it: `createPairInvite` refuses with `SyncError.existingPairing` (the pairing screen offers Rejoin when discovery found it, and only behind a confirmation `replacingExisting: true`, which deletes that zone first) — reusing it evicted the partner and handed the next joiner the whole history. The check fails closed (`leftoverZone` throws on a lookup it can't read; `reopened` refuses rather than evicts if a racing lookup let someone through), `CloudSync.memberCount` counts people once and never leavers, and `discoverExistingPairing` doesn't offer Rejoin into a share with a blocked person on it (`ownerShareIsRejoinable`; an unreadable share only when nobody is blocked). Mid-refresh guards compare the pairing by `PairingInfo.sameZone(as:)`, not by existence, so an unlink-and-re-pair spanning one refresh can't file the ex's delta or token onto the new pairing (`createPairInvite` clears tokens like `acceptShare` does). A change token cleared *during* `apply` (a corrupt moment index being rebuilt) is not written back. The owner's zone ID names *whoever is signed in*, so `requirePairing` and `unpair` refuse with `differentAccount` on positive proof of a mismatch (cached account lookup, `CloudSync.currentUserRecordName`); an unlink mid-refresh also stops `apply` filing anything past the status write and skips the token persist.
9. **Invite close is a two-step handshake, manual-only.** No single CKShare save converts a link-joined (public) partner to private: an in-place `role` flip is silently ignored (close included), and close+`addParticipant` in one save applies the close but drops the add (both verified against the live service, 2026-09). `lockPairing` therefore closes first (which sweeps the public joiner), then re-adds them via `CKFetchShareParticipantsOperation` (by `userRecordID` — nobody has email/phone `lookupInfo` since iOS 17) as an *invited pending* private participant; the partner confirms by tapping the invite link once (`receiveInvite`'s same-zone branch → `reacceptShare`). Verified end-to-end: link closed, partner private+accepted, sync intact. While pending the partner has no zone access, so the promote runs only after the owner explicitly asks — Settings' "Close the invite link" behind a confirmation (`AppModel.confirmingInviteReseat` → `closeInviteReseatingPartner`), or the Diagnostics button — never from a passive path (auto-close in refresh stays disabled). Any failure after the close goes through `restoreAfterFailedClose`, which retries the reopen and returns `couldNotSecureShare` (link open again) or `inviteLeftClosed` (it isn't: the partner is locked out until Settings' confirmed "Reopen the invite link"); `lockIfPartnerOnShare` refuses to report a closed, empty share as done. With nobody on the share, Settings' close is the plain `closeUnusedInvite`, which refuses with `SyncError.inviteInUse` once anyone is on it — it can never evict. `lockPairing` refuses with `SyncError.tooManyOnShare` when more than one person besides the owner is on the share (it would re-seat a stranger along with the partner). Prompting is not closing: Home's "\<partner\>'s in" card (`AppModel.showsCloseLinkPrompt`, shown only once the server said the link is open this launch) opens the same confirmation, and an owner refresh pass (hourly, `AppConfig.shareMemberCheckInterval`) counts the share's members for the "someone else has joined" warning — both only ever lead to the confirmed flow, and `closeInviteReseatingPartner` refuses while another close or reopen is running (its own flag, `isChangingInviteLink`; a posture check that overlapped one — started before it or during it — never overwrites it; Diagnostics' close goes through the same flag). Owner share calls refuse under a different iCloud account (`isPairingAccount`). Demo mode shows neither. No user-facing copy may say the link closes itself; `SettingsView.inviteFooter` and `InviteLinkSheet` describe the manual flow.
10. **Announcement dedup watermarks** live in `Snapshot`: `lastSeenPartnerNudgeCount`, `notifiedMomentIDs`/`lastNotifiedMomentID`, `lastAnnouncedPartnerStatusAt` + `lastAnnouncedPartnerStatus` (the words, so a rename is judged against what was last *announced*, never against a pre-refresh snapshot the widget may already have updated), `lastCelebratedAt`, `lastAnnouncedMomentSentAt` (the time floor the banner's index fallback searches past; `AnnouncementPolicy.claim` marks *every* moment in a burst announced and `bootstrapAfterPairing` seeds the floor, so neither a burst nor a re-fetched history can be described as new). The NSE and app both advance them; nudge watermark moves with `max()`, never assignment. **Every NSE banner is a claim** (`AnnouncementPolicy.claimStatusBanner`/`claimNudgeBanner`/`claimMomentBanner`); an unclaimed push is never credited to the partner — it is either our own write from a second device on this iCloud account (`RefreshResult.ownRecordsChanged`, judged against the held snapshot, so a full resync doesn't trip it; worded as such) or something another process already announced, and either way it is delivered `.passive` without sound — *except* when the NSE's own refresh skipped unreadable records (`RefreshResult.unreadableRecordNames` non-empty, a locked phone): the partner's event is real and nobody has announced it, so it stays at full volume, worded only from what travels unencrypted: when the unreadable records' *names* show the partner's moment or status, their name plus the moment's plaintext `kind` (`RefreshResult.heldPartnerMomentKinds`/`heldPartnerStatus`, `AnnouncementPolicy.heldMomentBody`), stamped `NotificationCategory.heldBannerKey` so the app's moment sweep supersedes it (the app posts no status notifications, so a held status banner stays); otherwise CloudKit's generic words. `claimMomentBanner` never falls back to re-describing an old moment. The status claim is skipped when `heldPartnerStatus` (the fallback `partnerStatus` is then the *previous* status), and no claim runs once the NSE's task is cancelled — the expiry fallback is already out, and a claim would bury the event. A moment the app posts over a generic or held banner goes out `.passive`: that push already alerted. A nudge push the NSE couldn't read (one batch of a large delta) keeps CloudKit's words at full volume, like any unreadable event.
11. **Offline sends recover, never silently drop.** Statuses: `Snapshot.myStatusPublished` + `Outbox.republishStatus()` (covers the `StatusLog` record too — `publish` writes both, and a failure on either keeps the flag down). Moments: `Moment.uploaded` + `Outbox.retryPendingUploads(automatic:)`. The anniversary: `Snapshot.anniversaryPublished` + `Outbox.republishAnniversary()` (owner only; `CloudSync.apply` leaves an unpublished local value alone so the republish wins, and only an explicit record *deletion* clears the date — a delivered record whose encrypted fields are unreadable, as happens in the NSE/widget on a locked device, keeps the stored copy, like `payload(from:)` does for statuses). The anniversary request: `Snapshot.anniversaryRequestPublished` + `Outbox.republishAnniversaryRequest()` (participant only, same fold rule). All re-run safely (fixed record names / overwrite semantics). Media is written locally before any network call. The home footer's "waiting to send" is a button (`AppModel.retryPendingNow`) over the same retry. A full iCloud (`SendFailure.storageFull`: `quotaExceeded`, bare or per-item) is named — whose storage, since the zone is the owner's and holds both people's sends — and automatic retries wait `AppConfig.storageFullRetryInterval`; the footer's tap still retries at once.
12. **`AppConfig` IDs must stay in lockstep** with the four entitlements files (app Debug and Release, widget, NSE), `project.yml`, and `Info.plist` `NSUbiquitousContainers`.
13. **Read receipts are double-gated and sticky.** `readReceiptsEnabled` gates both publishing and display; `Snapshot.receiptsDirty` + `flushReceiptsIfNeeded()` is the retry loop: the flag is claimed before the network call and re-set on failure, so a `markSeen` or toggle landing mid-flight is flushed by the next pass (same shape as the nudge cooldown), re-armed once per launch to heal misses; `MomentIndex.applyPartnerReceipts` never un-sees, and `MomentIndex.insert` keeps every local-only field (`seen`, `seenAt`, `seenByPartnerAt`, `uploaded`) sticky — a moment rebuilt from a CloudKit re-delivery carries none of them. Receipts fold into the index *after* a delta's moments are inserted. Disabling publishes an empty map and no status receipt. The **status** receipt (`Snapshot.partnerStatusSeen`, published; `myStatusSeenByPartner`, received) is stamped only by `AppModel.markPartnerStatusSeen` from the home screen while the app is `.active` and no sheet covers it (`homeSheetShowing`, `rootSheetShowing`; re-stamped when the last sheet closes), naming the status that screen shows — a background refresh, or a status landing under the picker, is not anyone looking — and only moves forward; it counts for display only while its `statusUpdatedAt` still equals `mine.updatedAt` or `mine.wordsAt` (a receipt from before my rename still means these words were seen).
14. **Status history dedups by `(fromMe, wordsAt)` from two sources.** The current `Status` record as its words change (`AppModel.setStatus`, `CloudSync.apply` — the own-status echo of a rename is skipped, like the partner's) and the per-change `StatusLog` records, which collapse into the same entry because both key on the whole-second `StatusPayload.wordsAt` — a `StatusLog` record is *named* by it. `wordsAt` is `updatedAt` unless a rename has since restamped the record: `wordsSince` is local only (never on the record, so older builds are untouched) and is carried across renames at ingestion (`payload(from:)`: same words *and* a changed name — re-picking the same status is a new one) and when renaming. Reports (`moderated(reportedAt:)`), celebrations, the status receipt and the partner card's time all key on it, so a rename changes none of them. Pruning is cloud-first: the publisher deletes its own records past the cap, and every device mirrors deletions via `StatusHistoryLog.remove`. Entries from before the cloud log existed are local-only and still don't survive a reinstall.
    **Persisted dates are whole seconds.** All App Group JSON encodes ISO-8601, which drops fractional seconds — a fractional `Date` never equals its own stored copy. `StatusPayload.updatedAt` is therefore truncated at creation (`AppModel.statusTimestamp`) and at CloudKit ingestion (`CloudSync.payload(from:)`); any new date used in an equality/watermark check must follow suit.
15. **Corrupt store files are preserved, not overwritten.** `SharedStore.decode`, `MomentIndex`, and `StatusHistoryLog` move unreadable bytes to a `.corrupt` sidecar before falling back to empty; the moment index also clears change tokens so CloudKit rebuilds it. Keep that pattern for any new persisted file. *Unreadable* is not corrupt: a moment index that exists but can't be read (before first unlock, an I/O error) sets `MomentIndex.readFailed`, nothing is saved over it, and `SharedStore.record`/`refreshDerived` skip pruning and the derived fields rather than act on an empty list (`insertReadable`/`loadReadable` return `nil`, judged under the index lock).
16. **Publish-success flags must verify currency.** `Snapshot.markStatusPublished(payload)` only flips `myStatusPublished` if the payload is still the current status — a late-finishing publish must not mark a newer offline edit delivered. `CloudSync.publish` therefore never writes an older payload over `mine`, and `saveStatus` skips when the server copy is newer. Renames publish with `logged: false` (no `StatusLog` record) — unless the status itself was never logged: `Snapshot.myStatusLoggedAt` records the `wordsAt` whose `StatusLog` is confirmed, and both the rename and `Outbox.republishStatus` log exactly when it differs. The receiver logs and announces renames as renames, not statuses. Status, nudge and anniversary saves use `.ifServerRecordUnchanged`, so a racing write surfaces as `serverRecordChanged` (bare or per-item) and `retryingConflicts` refetches and retries up to three times (under `.changedKeys` a race silently lost a write). A pre-field `myStatusLoggedAt` is seeded from a published `mine` at decode, so the first rename after upgrading doesn't log.
17. **Scrub gestures need `.highPriorityGesture`** (`ScrubbableWaveform`) in the gallery pager: a plain `.gesture` loses to the horizontal paging ScrollView, and waveforms must not be wrapped in a `Button` (see `VoiceMemoRow`). Inside a vertical ScrollView a high-priority drag hijacks scrolling instead — there pass `scrollSafe: true`, which swaps in `HorizontalScrub`, a UIKit pan that fails on vertical movement.
18. **Pin vertical-ScrollView content with `.containerRelativeFrame(.horizontal)`** (see `HomeView`). A child with a wide *ideal* size — a long single-line `Text` — can inflate the scrollable content's horizontal extent on some OS builds, letting the whole screen pan sideways; prefer `.fixedSize(horizontal: false, vertical: true)` on wrapping text too. (`WaveformBars` is safe: it condenses to what fits and never reports more than its measured width.)
19. **Never hold a shared-container file lock without a suspension guard.** Being suspended mid-`flock` is a `0xdead10cc` kill (TestFlight, 2026-09). `CrossProcessLock.withLock` holds a `performExpiringActivity` assertion for its critical section, so it's covered everywhere; async paths that end a UIKit background task (`withUploadProtection`) must do their post-await bookkeeping *inside* the protected closure, not after it.
20. **Moderation is local and sticky (App Review guideline 1.2).** `TermsView` gates everything until `SharedStore.acceptedTermsVersion` reaches `AppConfig.termsVersion`. A reported moment goes into `hiddenMomentIDs`, which `CloudSync.apply` filters from every delta (the record lives on in the sender's iCloud and resyncs re-deliver it); a reported status hides by `hiddenPartnerStatusAt`. Blocking (`AppModel.block`) records the partner in `blockedOwnerRecordNames` *before* the pairing is cleared, wipes locally even if the cloud unpair fails (the one place local-first is right), and `acceptShare`/`discoverExistingPairing` refuse those people. `ContentFilter` is word-level and applied to the partner's text only — UI, notifications and widgets alike — and *only through the presentation helpers in `Moderation.swift`*: `StatusPayload.moderated(reportedAt:)` (reported → no words and no emoji; filtered → placeholder), `StatusHistoryEntry.moderated`, `Moment.displayCaption`/`displaySenderName(fallback:)`, `Snapshot.moderatedPartnerName`. Names are user text and go through them too. A new surface that prints partner text calls one of these; the widget and the NSE read `hiddenPartnerStatusAt` the same way the home screen does. Reports are `mailto:` to `AppConfig.supportEmail` (no server); the 24-hour response is a commitment in the terms and on the site.

21. **No `.safeAreaInset(edge: .top)` over a scrolling list inside a `NavigationStack`.** A TestFlight watchdog kill (2026-09, iOS 26.6) caught the main thread looping between the navigation bar resizing and the sheet's `ScrollViewCommitMutation`: UIKit tracks the content scroll view's offset for the bar, SwiftUI's inset adjusts the same scroll view, and with enough rows to scroll they chase each other. `StatusHistoryView` and `MomentLibraryView` pin their filter picker with a plain `VStack` above the list instead.
22. **A save is confirmed by the record's own result, never by the call returning.** Every `modifyRecords` goes through `CloudSync.confirmSaved`/`confirmDeleted`: the async API throws for the operation, but a failed record can also arrive *inside* the result dictionary, and `_ =` on it marked photos sent on patchy signal delivered when the server never had them (participant side, 2026-09). Recovery is `MomentIndex.requeueMissingUploads`: after a complete full-zone fetch in the app (`previous == nil`, nothing more coming), own moments marked uploaded that the zone didn't return — judged by record *name*, so unreadable copies still count as present — go back in the retry queue if their media is still on disk; Diagnostics' "Re-check sent moments" (`AppModel.resyncHistory`) clears the tokens to force one. Uploads, refreshes, and the status, receipt, anniversary and subscription writes are bounded (`AppConfig.uploadDeadline`/`refreshDeadline`/`publishDeadline`; the app's nudge isn't — its cooldown release lives in `CloudSync.sendNudge` — and pairing/unlink calls are user-driven with their own UI): CloudKit's resource timeout is seven days, and a stalled operation held `isRetryingUploads`/`isRefreshing` — and with it every retry — until relaunch. `AppModel.refresh` holds `isRefreshing` for the fetch only (a request mid-fetch runs once more, not dropped); the republish/retry/receipt pass runs after it, outside the guard, coalesced the same way. A receipt write abandoned at its deadline can still land late (`.changedKeys`), so launch re-sends the receipts even with them off — a retraction it overtook heals.
23. **Nothing from the shared zone is trusted as sent.** The partner's build — or a modified one — writes these fields, and the share is read-write for both. At ingestion (`CloudSync.payload(from:)`, `moment(from:)`, `logEntry(from:)`): dates go through `TrustedTime.plausible` (at most the record's server `modificationDate` plus `AppConfig.clockSkewAllowance` — a *day*, so clocks deliberately set minutes ahead pass untouched and history/receipt keys still match; never before 1970 — ISO-8601 can't read a negative year back); the *partner's* text is capped (`statusMessageMaxLength`, `statusEmojiMaxLength`, `displayNameMaxLength`, `captionMaxLength`; own records aren't — `payload(from:fromPartner:)`); waveforms are finite and 0…1 (a NaN made the whole index unsavable); nudge counts are clamped to `nudgeCountCeiling` and incremented from the clamped value. Stored marks more than that day ahead of this phone's clock are treated as stale by `RefreshDelta.fold`, the announcement claims (a stuck moment floor reads as *now*, never as no floor), `recordAnnounced`, `pendingCelebration` and `MomentIndex.insert`, and `saveStatus` judges the server copy by the same cap. The 500-entry moment cap never drops a pending own send. A nudge breaks through Focus only when fresh and at most once per `nudgeBreakthroughInterval` (`AnnouncementPolicy.nudgeInterruption`, claimed with the nudge in one `mutate`).

24. **A fresh start clears only with both committed, each side its own records, by server time.** The asker's epoch is its `FreshStart` record's server save time (an ask is never re-saved, and never queued offline); the agreer names that epoch (agreement is final); the asker's app commits on seeing it — and a withdraw and a commit are both writes to the asker's own record under `.ifServerRecordUnchanged`, judged against the server copy (`FreshStartPolicy.transition`), so they can't both land. Only then does each phone's *app* clear (`Outbox.advanceFreshStart` → `CloudSync.clearHistory`): it re-reads both records from the server, deletes its own moments/`StatusLog`s created (server `creationDate`) before the epoch and its receipt — never `status-*`/`nudge-*` (read as an unlink), never the `FreshStart` record, never the current status's log — and only after that succeeds purges its own copy (`FreshStartPolicy.purge`: the zone's classification wins; an own send that never reached iCloud is kept and sent). Extensions read and fold the records but never write or delete. `Snapshot.freshStart.clearedBefore` (moved only by a *published* commit, max-only) keeps older moments/logs out of every delta at parse time — before readability, so they don't hold the token — and out of `requeueMissingUploads` (held off entirely while a `FreshStart` record is unreadable); the stores re-judge each insert *inside their locks* by server creation time (`FreshStartPolicy.clearedFilter`), so a batch another process parsed before the commit can't re-file what the clear purged; the clear and the upload retry never overlap. Our own record written by another account (`lastModifiedUserRecordID`, positive proof only, and only once this phone knows its own real record name — otherwise a failed lookup would wedge the clear) is never adopted as our consent.

25. **UIKit delegate callbacks with a completion run on the main actor — never `nonisolated async`.** The Objective-C thunk for an `async` delegate method calls UIKit's completion handler wherever the body finishes; for `UNUserNotificationCenterDelegate.didReceive` that completion updates the app snapshot, which asserts it's on the main thread ("Call must be made on main thread", TestFlight build 63: tapping a banner after the app had been suspended). `AppDelegate` conforms `@preconcurrency` so its witnesses can be main-actor isolated despite the non-`Sendable` `UNNotification`/`UNNotificationResponse`; keep any new async delegate witness the same way.

## CloudKit schema gotchas (summary — full detail in README "Shipping it")

- Production auto-creates nothing: deploy schema after Development use, and `cloudkit.share` only enters the schema when a share is actually saved in a Debug device build. The `Receipt`, `StatusLog`, `Anniversary` and `AnniversaryRequest` types likewise only appear after a Debug device has saved one (view a received moment with read receipts on; set a status; answer the date prompt as the owner; tap "Ask … to set it" on the count screen as the participant), and `Receipt`'s `statusSeenAt`/`statusSeenFor` fields only once a status has been on screen — deploy before shipping.
- Field encryption is fixed at creation; the CloudKit environment (Dev vs Prod) is decided by code signing, and mixed-environment devices can't see each other (looks like a broken pairing — see `CloudDiagnostics`).
- A second device on the *same* iCloud account (a Simulator signed in as you, another iPhone) is the same CloudKit user with the same `PairRole`: it writes `status-<role>`, `nudge-<role>` and `moment-<role>-…`, i.e. *your* records, and its writes fire *your* subscriptions. They show up as your own status/sends, never as the partner's, and the NSE words those pushes as "from another device" (invariant 10).
- `FreshStart` (fields `stage`, `epoch`, `clearedBefore`, all encrypted) only gets every field from a complete round between two Debug devices: ask on one, agree on the other, let both clear. Deploy before shipping.
- Subscriptions: `status-alerts` (visible, silent-sound), `nudge-alerts`, `moment-alerts` (both visible + sound + mutable content); legacy `status-changes` is deleted on sight.
