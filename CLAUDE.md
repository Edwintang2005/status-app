# Red String — agent guide

Two-person iCloud status app (iOS 17+, SwiftUI). One partner sets a status/nudge/photo/doodle/voice memo; it appears on the other's lock screen. No server: everything travels through CloudKit (a zone-wide `CKShare`), human-readable fields end-to-end encrypted via `encryptedValues`. Five shipping targets (app, widget extension, notification service extension, notification content extension, share extension) plus a unit-test bundle — all compile `Sources/Shared/`.

`README.md` is the deep reference (design rationale, share security model, Home layout, shipping/schema steps, demo mode, `make` targets) — read the relevant section before changing sync, pairing or notifications. `ROADMAP.md` is planned work, `CHANGELOG.md` what shipped. This file: the quick map + the invariants that must not break.

Comment style: comments are deliberately lean — one or two lines carrying only the non-obvious constraint or "why". Don't add narrative comments, restate code, or document history; match the existing density.

## Build & run

- `RedString.xcodeproj` is **generated** from `project.yml` (`make project`) but **committed** (Xcode Cloud needs it): after adding/renaming files, `make project` and commit the project too. Never edit project settings in Xcode's UI — they're overwritten. XcodeGen is pinned in `.xcodegen-version`; `make project` refuses any other version.
- `make build` is an unsigned compile check — never launch it (it traps on the App Group); other targets in README "Commands". Demo mode: `REDSTRING_DEMO=1` (Debug only) — `DemoBackend` + `DemoSeeder`, no iCloud.
- CI (`.github/workflows/ci.yml`), two parallel jobs, each uploading its `.xcresult` on failure: `test` — xcodegen drift check → unsigned Debug `build-for-testing`, warnings as errors (the simulator boots meanwhile) → unit tests (`test-without-building`) → UI tests compiled, not run; `release` — an unsigned Release build of the committed project (arm64, no dSYMs). Both Debug steps pass the same build settings, or the second rebuilds. dSYMs are Release-only (`project.yml`). Strict concurrency is `complete` (Swift 5 mode): zero warnings in every target. CI's Xcode (`^26.0`) can be older than yours and reject patterns a newer one accepts (e.g. a `@MainActor` task-group child) — a local pass isn't proof. The Pages site needs no workflow: GitHub Pages serves `main`'s `/docs` folder.
- `make test` runs `Tests/RedStringTests`, compiling `Sources/Shared/` directly (no host app, signing or App Group): the stores (Codable fallbacks, watermarks, merging, `GroupFileStore`/`CrossProcessLock` on temp directories), ingestion caps, and every pure decision type (`ParsedDelta`, `RefreshDelta`, `TokenAdvancePolicy`, `AnnouncementPolicy`, `PushBannerPolicy`, `Outbox` over `FakeBackend`, `FreshStartPolicy`, `SharePosture`, `TimelinePlan`, …), and the sequencing around them: `CloudSync.refresh`/`unpair` over `FakeCloudDatabase` (`CloudSyncSeamTests`: `CloudSync(stores:database:prefetchesMedia:)` — `CloudStores` of temp stores, no container), `SyncCoordinator` over a host recorder, `SyncRunner` over `FakeBackend`. **Keep decisions in those types:** `CloudSync.apply` performs what `ParsedDelta` decides, `AppModel` hands send loops to `Outbox` (`Outbox.testing`) and fetch timing to `SyncCoordinator`, `SyncRunner`/`NotificationService` apply `PushBannerPolicy`. `IngestTests.testTheChangeFetchAsksForEveryNonAssetField` reads `CloudSync.swift`'s `Field` block, so a field missing from `CloudSync.changeFetchKeys` fails. Stores take an injected URL, directory or `UserDefaults` suite — **never a `.shared` singleton in a test**: the host-less bundle resolves the simulator's real App Group container and writes the installed app's data (`SharedStore`'s static locks still do, lock files only). `MomentIndex`/`StatusHistoryLog` keep their lock file beside their data file, so a test's lives in its temp directory; pass `onCorrupt: {}`, or a corrupt test file clears the real container's change tokens. `TestSupport.swift`: `Fixtures` (`zone`, `statusRecord`) and `waitUntil` — wait on conditions, never sleep.
- `make uitest SIM=...` runs `Tests/RedStringUITests`: a demo-mode smoke over Home and every main sheet (the drawing palette too) with `performAccessibilityAudit()`, a launch-hang guard (every screen must answer a query in time; invariants 18, 21) and `assertFitsScreen` (nothing hangs past the window's sides); `make uitest-narrow` runs it on the 375 pt iPhone SE (3rd generation). Signed, so CI only compiles it. Exclusions (`DemoSmokeTests.accepts`: Dynamic Type wholesale — `Theme.rounded` doesn't follow a live size change, on ROADMAP — system chrome, disabled controls, emoji, screenshot-checked misreads) stay narrow and commented.
- User-facing text: `Text` literals, `String(localized:)` elsewhere; each target's `Resources/Localizable.xcstrings` is filled by an Xcode IDE build (xcodebuild leaves it empty — harmless). Icon-only controls carry an `accessibilityLabel`; `Theme.rounded` follows Dynamic Type (capped at 1.35×).

## Architecture (data flow)

```
UI (Views/) → AppModel (@MainActor, @Observable)
            → Backend.current (SyncBackend protocol: CloudSync actor, or DemoBackend)
            → CloudKit custom zone "CoupleZone", zone-wide CKShare

SharedStore (App Group, file-backed KV via GroupFileStore)  ← app / widget / NSE all read+write
  ├─ Snapshot        widget-renderable cache: both statuses, nudge watermarks, latest moments
  ├─ PairingInfo     role (owner/participant) + zone coords + account userRecordName
  └─ change tokens   one per database (changeTokenKey(for:), clearChangeTokens())

MomentIndex       moments-index.json — history metadata (cap 5,000)
MomentStore       /Moments — full JPEG + square thumb, .m4a; full media for the 60 newest, thumbs for the 500 newest (MediaRetention)
StatusHistoryLog  status-history.json — both sides' statuses (cap 300 in all, room for both sides' cloud logs of statusLogLimit, 150, each)
SyncCoordinator   when the app fetches (launch, foreground, push, network back) and the recovery pass after; AppModel is its host
SyncRunner        refresh → decide what to announce → notifier (the app's NotificationManager)
NotificationService  enriches CloudKit pushes: refreshes, decrypts, rewrites banner, reloads widgets
```

`SyncBackend` carries every CloudKit call the app makes, pairing and share included (`AppModel` never calls `CloudSync.shared` except the DEBUG sweep; `DiagnosticsView` reads `CloudSync.shared.diagnostics()` directly); `DemoBackend` stamps locally what `CloudSync` would.

Records (`PairRole` derives every per-side name; neither device needs the other's user ID): `status-<role>`; `statuslog-<role>-<seconds>` (one per change, the durable history, pruned by its writer); `nudge-<role>` (its own record type, so its push can be visible + sound); `moment-<role>-<uuid>` (kept forever); `receipt-<role>`; `anniversary` (owner-written); `anniversary-request` (participant-written); `freshstart-<role>`. The last four have no subscription; they ride any refresh.

## Invariants — do not break

1. **Cross-process locking.** App, widget and NSE run concurrently: every read-modify-write of `Snapshot` goes through `SharedStore.mutate` (flock, `CrossProcessLock`), `MomentIndex`/`StatusHistoryLog` lock likewise, and check-and-claim decisions happen *inside* one `mutate`.

2. **Apply before token, media after both; what couldn't be read is owed.** `CloudSync.refresh` folds records in before persisting the change token (else an NSE killed on deadline loses them) and only performs `TokenAdvancePolicy.persists(samePairing:startedFrom:storedNow:)` — a compare-and-swap: written only over the bytes its fetch began from, so neither a token cleared during `apply` nor another process's newer one is overwritten.
   - Media (`prefetchMedia` running `MediaPrefetchPlan`) downloads after the token, never in `apply` — no record needs it, and downloads there held the NSE's banner. It stops at cancellation or a changed pairing, and deletes a download that lands after an unlink.
   - A record whose encrypted fields come back empty (`CloudSync.isReadable`, probed on a field every version writes) — or that the fetch reported but couldn't hand over (`ZoneChanges.failedIDs`, also counted present by `requeueMissingUploads`) — is skipped, listed in `RefreshResult.unreadableRecordNames`, and **owed** (`SharedStore.UnreadableTally.owed`, via `noteFetched` under its own lock, only for the pairing fetched): the token moves on, so neither a locked phone's extensions nor a record nobody can read pins the delta behind it. Any record read, or deleted, in a later delta settles it.
   - Except a **resync** batch that misses records in a process without the keys (an extension's, or the app's with protected data unavailable), or more than the owed list has room for (`CloudSync.ResyncHold`): it keeps its token and owes nothing — its records come round with the batch — and is recorded as `UnreadableTally.held` (the partner's moments and status and the fresh-start records only, newest `owedRecordLimit`; `heldCount` the whole) for the held banners and the widget, replaced each held pass, cleared by any that keeps a token; it isn't a complete sync (no `lastSyncedAt`). The over-room hold ends after `heldResyncGiveUpPasses` spaced looks by the app with its keys: it then owes what fits and counts the rest `abandoned`, rather than re-fetching the zone forever.
   - A pass that missed anything doesn't move `Snapshot.newsAfter` (`readUpTo`): a missed record may be older than what it read. A resync's misses are owed with the mark that pass judged against (`apply`'s `judgedNewsAfter` → `OwedRecord.resync`/`newsAfter`), and whichever pass reads an owed moment judges it as missed (`ParsedDelta.OwedNews`: incremental → news; resync → its kept mark).
   - `CloudSync.retryOwedRecords` fetches owed records by ID (`CloudDatabase.fetchRecords`, `.userInitiated`, ≤ 200 per call) after a pass that missed nothing — the app only with protected data, the widget and expanded banner on any pass with budget left (`owedRetryExtensionBudget`; they're what catch up after an unlock), never the notification service (its time is the banner's). The claim is cross-process (`SharedStore.claimOwedRetry`: once per `owedRetrySpacing`, `owedRetryBlindSpacing` for an extension after a retry that read nothing; an extension only the newest `owedRetryExtensionLimit`), skipped once cancelled; a quick failure gives it back, a stall (its own `owedRetryDeadline`/`owedRetryExtensionDeadline`, or the pass's) keeps it as a blind try, so a stall is never paid on every pass and can't fail the pass it follows. Records go through `apply` as one batch of many (no `lastSyncedAt`, no `newsAfter`) in a fixed order (`CloudSync.retryGroups`): a resync's misses first, by kept mark, then the rest incrementally; still-unreadable ones join `unreadableRecordNames`; `unknownItem` settles. An entry older than `owedRecordLifetime` (30 days), or past `owedRecordLimit`, is given up (`abandoned`). `heldNames` and `heldSince` (the *latest* miss) cover owed and held records, for the held banners, `BannerUpkeep`'s `caughtUp` (nothing held), the widget's schedule, Diagnostics, and — while a miss is under `AppFetchPolicy.owedRecentlyWindow` (a day) old — `AppFetchPolicy` and the NSE's `wholePushID`/`widgetNeedsFetch`.
   - Unreadable never means absent: `MomentIndex.insert` keeps held captions/names/waveforms (a copy with caption *and* sender name empty is unreadable; a readable one with an empty caption is a removed caption), `logEntry(from:)` writes no placeholder, `RefreshDelta` clears the anniversary or status receipt only on an explicit deletion / readable receipt.
   - The NSE's attachment is bounded (`PushBannerPolicy.attachmentDeadline`: ≤ `widgetDeadline`, never into its last 5 s). Its refresh downloads nothing before the banner is worded and claimed (`CloudSync.refreshDeferringMedia`): the delta's media follows within what's left of that bound, before a carried moment is posted; skipped for want of time, the widget is asked to fetch (`widgetNeedsFetch`), and its prefetch includes the picture it draws (`latestPartnerVisualMoment`) though no delta brought it.

3. **Shared state lives in files, not UserDefaults** (unreliable across the App Group — see `GroupState.swift`). Caches key on the file so another process's write is always seen: `GroupFileStore` caches bytes by `FileIdentity` (device, inode, size, mtime), `SharedStore.decode` reuses a value only for identical bytes, `MomentIndex`/`StatusHistoryLog` cache by file identity.

4. **Encryption boundaries.** Text and behavioural fields (`emoji`, `message`, `displayName`, `caption`, `senderName`, `waveform`, `isCelebration`/`celebrationStyle`, `seenMap`/`statusSeenAt`/`statusSeenFor`, `startsAt`/`timeZone`, `requestedAt`, the fresh start's fields) go through `record.encryptedValues`. Plaintext by design: record names, moment `kind`/`sentAt`/`duration`/`momentID`, nudge `count`/`sentAt`, `updatedAt` (locked-phone banners need `kind`). `CKAsset`s, encrypted by CloudKit, must NOT go through `encryptedValues`; a photo's place rides inside its full-size asset (`PhotoLocation`), never as a field. Plaintext user words are a privacy regression.

5. **Hand-written Codable.** `Snapshot`, `StatusPayload`, `Moment`, `PairingInfo` (only the zone's role and names required — a `nil` pairing reads as unlinked) decode with `decodeIfPresent` + fallbacks so old data survives; new persisted fields follow suit (mind what the fallback means for legacy data). `Snapshot.CodingKeys` is `CaseIterable`, checked against the stored properties by `SnapshotCodableTests`; `Snapshot()` builds the defaults.

6. **Widgets reload via `SharedStore.reloadWidgets()`** after a snapshot/media change, never from the widget process (`isRunningInWidgetExtension`); in-process calls use the instance (`requestWidgetReload`), so a test store stamps itself.
   - An app/NSE reload stamps `widgetReloadRequestedAt` and the widget skips its fetch for `WidgetReloadPolicy.siblingReloadWindow` (2 min); `reloadWidgets(widgetNeedsFetch: true)` clears it (the NSE after an incomplete batch, failure or expiry). The NSE holds reloads for its run (`holdWidgetReloads()`, one idempotent release per exit).
   - The app also redraws when it comes to the front and after its first fetch to work following a failure (`AppModel.redrawWidgets`, front-only: WidgetKit doesn't count those), so an outage's stale timeline never needs a restart. The widget records each run (`SharedStore.lastWidgetRun`, carrying the last real fetch through redraws that skipped one) for Diagnostics.
   - Otherwise reload only when something drawn moved: a `mutate` that changes nothing writes nothing and reloads nothing (an identical encode isn't rewritten either: `JSONEncoder.shared` sorts keys), `refreshDerived` compares `SharedStore.Derived` (ids, kinds, captions, names, memo count — never `seen`); an empty refresh reloads only if the fold changed the snapshot; the gallery reloads once on dismiss (`flushWidgetReload`). Widget kinds share one refresh (`SingleFlight`).

7. **Cooldown claims before network.** `CloudSync.sendNudge` claims the cooldown inside the lock before the call; a failure releases it and stamps `lastNudgeFailedAt` (the lock-screen heart's only error channel). A lock-screen send abandoned at its deadline is released by `NudgeCooldownPolicy.releaseAbandoned` — only if the standing claim is that tap's, never landed, and was never handed to iCloud (`lastNudgeIssuedAt`, stamped just before the save: from there it lands on its own, and a "didn't send" only invited duplicate taps). The save is one round trip from the cached record (`SharedStore.nudgeRecordCache`, refreshed by every save and every delta carrying our nudge record), a long-lived operation never cancelled once handed over; the heart's ✓ runs from the hand-off (`nudgeSentNotice`). The app's heart holds `AppModel.isSendingNudge` over its unbounded call ("Sending…"; a second tap is dropped).

8. **Unlink is cloud-first.** `unpair()` succeeds before local state is cleared; `forceLocalReset` is the escape hatch. "Zone gone" under a *different* iCloud account never wipes (`SyncError.differentAccount`).
   - **"Zone gone" needs a second sighting** (`CloudSync.zoneGoneVerdict`), since the close handshake takes the partner off the share for seconds: the first stamps `SharedStore.zoneGoneSeenAt` and throws the transient `SyncError.zoneUnreachable`; one `zoneGoneConfirmation` later wipes and throws `linkEnded`; a successful fetch clears the stamp.
   - That wipe spares own unsent sends (`eraseLocalMedia(keepingPendingUploads: true)`) and remembers the zone (`clearPairing(keepingName: true)` → `SharedStore.lastPairing`); `acceptShare`/`rejoin` (`adoptPairing`) skip the wipe for that zone, so the re-tapped link re-sends them. A different zone, a new invite or "start over" wipes.
   - A new invite never reuses a zone with someone on its share or any records: `createPairInvite` refuses with `SyncError.existingPairing` (Rejoin offered; `replacingExisting: true`, confirmed, deletes the zone first). It fails closed — `leftoverZone` throws on an unreadable lookup, `existingZoneShare` on anything but "gone", `reopened` refuses rather than evicts. `SharePosture.memberCount` counts people once, never leavers. `discoverExistingPairing` doesn't offer Rejoin into a share with a blocked person (`ownerShareIsRejoinable`; an unreadable share only when nobody is blocked).
   - Mid-refresh guards compare by `PairingInfo.sameZone(as:)`, so an unlink-and-re-pair can't file the ex's delta or token on the new pairing (`createPairInvite` clears tokens like `acceptShare`); an unlink mid-refresh stops `apply` past the status write and skips the token persist; a token cleared *during* `apply` isn't written back.
   - The owner's zone ID names *whoever is signed in*: `requirePairing`/`unpair` refuse with `differentAccount` on positive proof of a mismatch (`CloudSync.currentUserRecordName`, cached). `refresh` runs that check alongside its fetch, judged before `apply` and the verdict; a cold extension first trusts `SharedStore.verifiedAccount` (same `accountCacheLifetime`, never future-stamped), cleared by `noteAccountChanged`.
   - **Subscriptions outlive an unlink that didn't reach iCloud:** `finishUnlink` (unlink, block, local reset) and the verdict stamp `SharedStore.subscriptionCleanup` with the pairing's account; `AppModel.cleanUpSubscriptionsIfNeeded` retries each foreground while unpaired, bounded, deleting `SubscriptionID.all` from both databases (`unknownItem` = done), refusing on proof of another account, never while paired, re-registering if a pairing appeared mid-delete.

9. **Invite close is a two-step handshake, manual-only.** No single `CKShare` save makes a link-joined (public) partner private (a `role` flip is ignored; close + `addParticipant` drops the add — verified live). `lockPairing` closes (sweeping the public joiner), then re-adds them by `userRecordID` via `CKFetchShareParticipantsOperation` (no `lookupInfo` since iOS 17) as an *invited pending* private participant, confirmed when they tap the link once (`receiveInvite` same-zone → `reacceptShare`).
   - Pending, the partner has no access, so it runs only on the owner's confirmed ask — Settings' "Close the invite link" (`AppModel.confirmingInviteReseat` → `closeInviteReseatingPartner`) or Diagnostics — never passively (auto-close in refresh stays disabled). Prompts only lead there: Home's "\<partner\>'s in" card (`showsCloseLinkPrompt`, once the server said the link is open this launch) and the hourly member count (`shareMemberCheckInterval`, "someone else has joined").
   - A failure after the close goes through `restoreAfterFailedClose`: `couldNotSecureShare` (reopened) or `inviteLeftClosed` (partner locked out until Settings' confirmed "Reopen the invite link"). `lockIfPartnerOnShare` never reports a closed, empty share as done. With nobody on the share, the close is `closeUnusedInvite`, refusing with `SyncError.inviteInUse` once anyone is on it — it can't evict. `lockPairing` refuses with `SyncError.tooManyOnShare` beyond one person besides the owner (it would re-seat a stranger along with the partner).
   - Closes, reopens and the DEBUG sweep (`AppModel.sweepPublicJoiners`) run under `isChangingInviteLink` and refuse while another runs; a posture check overlapping one never overwrites it.
   - Owner share calls go through `ownerPairing()`/`requireOwnerPairing()` (owner role, account available, the pairing's account — `isPairingAccount`); share saves confirm via `savedShare`. Demo mode shows neither prompt nor warning. No copy may say the link closes itself (`SettingsView.inviteFooter`, `InviteLinkSheet`).

10. **Announcement dedup watermarks** live in `Snapshot`: `lastSeenPartnerNudgeCount` (`max()`, never assignment), `lastAnnouncedPartnerStatusAt` + `lastAnnouncedPartnerStatus` (the words: a rename is judged against what was last *announced*), `lastCelebratedAt`. App and NSE both advance them.
    - **Moments are owed, not reconstructed.** The fold (`RefreshDelta`, inside `apply`'s locked `mutate`) files each partner moment the delta made news into `Snapshot.owedMoments` (the moments themselves: no announcer reads the index), refreshes an owed copy's words when it's re-delivered, and drops deleted ones; seen in the app (`markSeen`), reported, or cleared by a fresh start, it's settled too. Announcing is `AnnouncementPolicy.takeOwedMoments`: the whole list taken in one `mutate`, one banner for the last to *arrive* (never by `sentAt`, the partner's clock), so a burst is one banner. Taken ids go into `notifiedMomentIDs` (bounded), which `owe` skips — two passes can fold one delta at once. `lastNotifiedMomentID` is the last banner's moment.
    - **The NSE's branch table is `PushBannerPolicy.decide`**: claims and words in one `mutate`; `NotificationService` applies the plan, whose worded content is the expiry fallback (`setFallback`) — set before anything else is awaited, the carried moment's post included.
    - **Every banner is a claim** (`claimStatusBanner`/`claimNudgeBanner`/`takeOwedMoments`); an unclaimed push is never the partner's: it's another device on our account (`RefreshResult.ownRecordsChanged`, judged against the held snapshot so a resync doesn't trip it; worded so), this phone's own heart pushed back to it (no `partnerNudgeArrived`, and `RefreshResult.ownNudgeSentAt` — or, with nothing new read because the widget's own refresh took the save first, our `lastNudgeAt` being the space's latest — within `nudgeEchoWindow` before `lastNudgeSentAt`: "Your heart was sent to …"), this phone's own status or moment coming back (statuses: ours the space's newest, server save time when both carry it; moments: `RefreshResult.ownMomentSent`, or with nothing read — `momentsArrived` false — our newest uploaded, within `nudgeEchoWindow` and newer than theirs: "Your status/moment was sent to …"), or already announced (its words again; nothing knowable: "Your shared space changed.", never CloudKit's generic words) — `.passive`, no sound, and `willPresent` only lists a `.passive` *push* (the app's own passive posts still show). Status pushes get their sound from the NSE's plan (`Plan.sound`: the subscription is silent and fixed) only for a claimed partner update/rename or a held partner status — an unworded pass may be our own save. Nothing owed, no moment is described: re-fetched history is never owed; `claimStatusBanner` orders by `StatusPayload.serverSavedAt` when both copies carry it.
    - **The receiver's `NotificationPreferences` cap every banner last** (per kind — statuses, hearts, pictures, voice memos — `sound`/`silent`/`list`; per device in `SharedStore`): the NSE caps its content before anything is read (the expiry fallback; a moment push at the louder of pictures and memos) and its plan after `decide` (`Plan.limited`, at the loudest kind the pass read); the app's own posts use `UNMutableNotificationContent.limit(to:)`, whose "list only" stamps `NotificationCategory.listOnlyKey` so `willPresent` lists it. Never louder than chosen, never dropped.
    - **Unreadable or incomplete delta** (locked phone; one batch of many): real and unannounced — full volume, worded from plaintext only. If the held records' *names* show the partner's moment or status: their name + the moment's `kind` (`heldPartnerMomentKinds`/`heldPartnerStatus`, `heldMomentBody`), stamped `NotificationCategory.heldBannerKey` so the app's moment sweep supersedes it (a held status banner stays — the app posts no status notifications); otherwise, nudges included, CloudKit's generic words. A banner left in CloudKit's words — refresh failed, expiry before wording, an unchanged plan — is stamped held (`Push.unwordedSubject`): a status one with `.status`, so `BannerUpkeep` can reword it (it may be our own status coming back, so one still in CloudKit's words whose reword doesn't claim is withdrawn; a held one that named them keeps its words); a moment one with `.newMoments`, withdrawn once nothing is owed — judged only after a whole-delta fetch with nothing held (`BannerUpkeep.run(caughtUp:)`), or it may be that very moment not here yet (an edit, a deletion) — and swept by `postMoment` otherwise; the NSE records each pass's outcome for Diagnostics (`SharedStore.lastBannerPass`), naming the row it took (`PushBannerPolicy.decideRow` → `Row`). Under `heldPartnerStatus` the status claim is skipped (the fallback `partnerStatus` is the previous one).
    - **Banners carry their subject** (`BannerSubject` in `userInfo`: `.moment(id)` — a held burst's newest — `.status`, `.hearts`; `wantsAttachmentKey` when the picture missed the deadline). A push banner with no subject — the service never ran — still in CloudKit's words is inferred from its subscription (`BannerUpkeepPolicy.inferredSubject`: status → `.status`, moment → `.newMoments`, never a heart) and handled as held; a status reword stamps the subject. Hearts share `NotificationThread.hearts` (each still its own banner; our own echo isn't one). DEBUG: each process records a `SharedStore.BannerProbe` (listing, rewrite in place) for Diagnostics. `BannerUpkeep` runs `BannerUpkeepPolicy` after every refresh — app (`SyncRunner`), NSE (with its own push as `incoming`), widget, the expanded banner — since nothing runs at unlock: held → reworded once readable, a late thumbnail attached, a gone/reported moment's banner (or a held one no longer held nor filed) withdrawn, a delivered banner for the service's own `incoming` moment replaced, every status banner kept — together they're the unread history; only the newest, if held, takes the stored (latest) words, an older held one that named them keeps "updated their status" and one still in CloudKit's words goes once the newest is judged (it may be our own echo), and an announced moment's banner whose words no longer match (`State.wordings`: its caption, or the edited-caption notice) refreshed quietly — an edit another process filed first. A reword is the claim (`BannerUpkeepPolicy.claimReword`, `AnnouncementPolicy.claimStatusBanner`, in one `mutate`): already announced → withdrawn instead, so nothing alerts twice; `postMoment` also sweeps a banner with its subject. A rewrite re-adds the banner's own identifier only if still delivered, `.passive`, stamped `revisedKey` (`willPresent` lists it); never louder; an attachment iOS refuses isn't asked for again. The NSE tidies up after its own attachment, bounded. A photo/drawing banner's tap routes to `.moment(id)` (a memo's, to the new arrivals).
    - No claim once the NSE's task is cancelled (it would bury the event the fallback already shows). A moment the app posts over a generic or held banner is `.passive`.
    - **A moment another pass filed is still announced, once.** A heart or status push takes what's owed in the same `mutate` (`PushBannerPolicy.carriedMoment`) and the NSE posts the newest's own banner beside its own (`MomentBanner`, the app's identifier, so never twice) — APNs keeps one notification per app for an offline phone, so the moment's push may never come. One the widget or expanded banner filed stays owed until the app's next refresh takes it. Own-doing banners (`own`, `spaceChanged`) drop the category — nothing to reply to; a quiet repeat of an announced moment keeps its picture.
    - **Partner leaving** (`RefreshResult.partnerLeft`, or `Snapshot.partnerHasLeft` filed elsewhere): every unlink push reads "<name> left your shared space", quiet, no category, claiming `partnerLeftAnnounced` so `SyncRunner` posts its passive notice only if no push did. Deletion-only moment pushes are worded and quiet; a count-less nudge push is never a heart; unpaired pushes (`PushBannerPolicy.unpaired`) are quiet, neutral, action-less.
    - In a **full resync** (`RefreshResult.fullResync`) an unknown moment is news only if the server created it after `Snapshot.newsAfter` — the newest server save a complete fetch read, the server's clock throughout; none after a new pairing or a reinstall (`AnnouncementPolicy.isNews`; always encoded, null included, and a mark over a day ahead is replaced at the next complete fetch); incrementally it always is (an offline send arrives late). Unknown moments older than the index's last entry (`momentHistoryLimit`, 5,000) are neither filed, news, nor another device's write.

11. **Offline sends recover, never silently drop.** Republishes re-run safely (fixed names, overwrite); media is written locally before any network call.
    - Statuses: `Snapshot.myStatusPublished` + `Outbox.republishStatus()`, covering the `StatusLog` too (either failing keeps the flag down). Saved but not logged = sent with a log owed (`myStatusLoggedAt != wordsAt`): the republish sends only the log (`StatusSavePolicy.alreadySaved`), no repeated pushes. Repeated non-offline failures back off. A status or rename publish runs under `withUploadProtection`, like every other send.
    - Moments: `Moment.uploaded` + `Outbox.retryPendingUploads(automatic:)`, every send through `Outbox.upload`: `uploadsInFlight` keeps retries off a send still uploading (and out of `pendingUploadCount`) — until the upload itself ends, not when its caller stops waiting; the `uploaded` callback stamps `sendConfirmedAt`, retries included.
    - Weak signal: an upload is a long-lived `.userInitiated` operation (`.utility` retries network errors silently, hiding offline), cancelled only once stuck (`UploadWatch`: no change in progress for `uploadStallTimeout`, twice that before the first byte and after the last; a suspension gap restarts the clock), never for being slow. A retry pass goes smallest first (`UploadOrder`) and stands aside while any upload runs; any landing (a background one a refresh already filed included) with the link then idle calls `linkFreed` (`AppModel` → `sendQueued`), and the footer says "Sending…" while any is in flight (`AppModel.isUploading`). Every pass and the fresh start's clear first await `adoptBackgroundUploads` (`resumeUploads`: last launch's long-lived uploads, never this process's own; another zone's is cancelled; a failed look is retried). A landing after the pairing moved isn't marked sent, and `withZoneRecovery` judges "zone gone" only for the current pairing.
    - Deletes (own moments, `Moment.canDelete`: within `momentDeleteWindow` or never uploaded; the partner's are never deletable): `Outbox.deleteMoment` removes it here at once and files `SharedStore.pendingMomentDeletions`, which `CloudSync.apply` treats like `hiddenMomentIDs` until `Outbox.sendDeletions` (`CloudSync.deleteMoments`: non-atomic, confirmed per record, `unknownItem` = done) clears it. It stands aside for any upload in flight, last launch's adopted first, and a landing of a deleted moment shows no "Sent". Receivers: `ParsedDelta.outcome` files a seen partner moment removed within `removalNoticeWindow`, after any fresh start's epoch, into `Snapshot.removalNotices`; the NSE or the app claims them (`AnnouncementPolicy.claimRemovals`) — "removed a moment", not quiet.
    - Caption edits (own moments): `MomentIndex.editCaption` files them (`captionPublished` false, `captionEditedAt`), `Outbox.republishCaptions` sends uploaded ones (`CloudSync.updateCaption`: caption-only fetch, `.ifServerRecordUnchanged`, a gone record is done) and marks only the words that went; insert keeps a pending edit over any fetched copy, and the parse compares against *published* captions only. Receivers: `RefreshResult.editedPartnerMoments` → a quiet "edited a caption" banner with the moment's subject, replacing the old one; never news. This phone's own edit coming back (`ParsedDelta.ownEditEchoes`: owed or edited within `nudgeEchoWindow`, sent before it) is `ownCaptionEditSent`, "Your caption edit was sent", never a send.
    - Anniversary (`anniversaryPublished` + `Outbox.republishAnniversary()`, owner only) and request (`anniversaryRequestPublished` + `republishAnniversaryRequest()`, participant only): every set or ask goes through them; a value changed mid-send is resent once it lands (`supersededResendLimit`). `CloudSync.apply` leaves an unpublished local value alone; only an explicit *deletion* clears it (an unreadable delivery keeps the stored copy, as `payload(from:)` does for statuses).
    - Offline, sends are still *tried*: `AppModel.isOffline` is display only (stale while suspended; a banner action wakes the app first). `SendFailure.offline` (`networkUnavailable` only; `networkFailure` stays transient) is quiet — the offline card, the footer count (`pendingSendCount`: moments + `Snapshot.unpublishedCount`, incl. a queued fresh start answer) and "Waiting to send", never an alert per send. The reconnect catch-up (`SyncCoordinator.catchUpAfterReconnect`) fetches, retried per `reconnectRetryDelays` until one since the edge worked (`lastFetchSucceededAt`), then only re-runs the recovery pass until nothing is queued — never a fetch per delay.
    - A send iCloud refuses outright (`SendFailure.rejected`: invalid arguments, a refused request, a schema without the field, a missing asset) isn't re-uploaded every refresh: an automatic retry pass skips that moment for `rejectedUploadRetryInterval` (in memory, so each launch tries once); never dropped, and a tap retries at once.
    - Full iCloud (`SendFailure.storageFull`: `quotaExceeded`, bare or per-item) is named — whose: the owner's zone holds both people's sends — and automatic retries wait `storageFullRetryInterval`. A throttle (`SendFailure.throttled(until:)`: `requestRateLimited`, `zoneBusy`, `serviceUnavailable`; retry-after capped at `AppConfig.throttleMaxDelay`, an hour) holds every automatic loop alike — the recovery pass's receipt flush and fresh-start step included (`automatic: true`). A throttled change fetch stamps `SharedStore.fetchThrottledUntil` for every process: the app's automatic fetches (`SyncHost.fetchThrottled`, skipped without counting as a failure) and the widget's wait it out; pull-to-refresh (`SyncCoordinator.refresh(asked:)`, held as `askedPending` so a later caller's queued rerun can't drop it) and the notification service's fetch don't. The footer's "waiting to send" (`AppModel.retryPendingNow`) always retries at once.

12. **`AppConfig` IDs stay in lockstep** with the six entitlements files (app Debug and Release, widget, NSE, notification content, share), `project.yml`, and `Info.plist` `NSUbiquitousContainers`.

13. **Read receipts are double-gated and sticky.** `readReceiptsEnabled` gates publishing and display. `Snapshot.receiptsDirty` + `Outbox.flushReceipts()` is the retry loop: claimed before the call, re-set on failure, so a `markSeen` or toggle mid-flight goes next pass. A claim marks them `receiptsUnsettled`; only a confirmed write settles them, and not once a write in this process was abandoned (it can land late, over a newer one) — launch re-arms only unsettled receipts (`rearmUnsettledReceipts`). With every field set the save skips the fetch (`.changedKeys` checks no change tag); a retraction (no status receipt) fetches first, so its removals count. Writes are debounced (`scheduleReceiptFlush`, 5 s) and flushed in a background task on backgrounding (a flush already under way when the app backgrounds isn't covered: the call returns at once); the toggle and recovery pass flush at once. Off publishes an empty map and no status receipt.
    - `applyPartnerReceipts` never un-sees; `MomentIndex.insert` keeps local-only fields (`seen`, `seenAt`, `seenByPartnerAt`, `uploaded`, `favouritedAt`) over re-deliveries. Receipts fold in *after* a delta's moments.
    - The **status** receipt (`Snapshot.partnerStatusSeen` out, `myStatusSeenByPartner` in) is stamped only by `AppModel.markPartnerStatusSeen` from Home while `.active` with no sheet over it (`homeSheetShowing`, `rootSheetShowing`; re-stamped when the last closes), naming the status shown — a background refresh or a status under the picker isn't anyone looking. It stamps **`wordsAt`**, forward only (a rename neither re-stamps nor loses it), and only once the words are shown (`StatusPayload.wordsShown`: reported, or filtered and not revealed via `AppModel.revealPartnerStatus`, stamps nothing). It displays only while its `statusUpdatedAt` equals `mine.updatedAt` or `mine.wordsAt`.

14. **Status history dedups by `(fromMe, wordsAt)`** across the `Status` record as its words change (`AppModel.setStatus`, `CloudSync.apply`; a rename's own echo is skipped) and the `StatusLog` records, *named* by the whole-second `StatusPayload.wordsAt`.
    - `wordsAt` is `updatedAt` unless a rename restamped the record. `wordsSince` is local only, carried across renames at ingestion (`payload(from:)`: same words *and* a changed name — re-picking a status is new), when renaming, and for the *same version* (equal `updatedAt`, same words) in `payload(from:)` and `RefreshDelta`'s merge. Reports, celebrations, the status receipt and the card's time key on it, so a rename moves none of them.
    - `StatusPayload.serverSavedAt` (local, whole seconds) orders the partner's copies when both carry it — their `updatedAt` is their phone's clock.
    - Pruning is cloud-first: the publisher deletes its own past the cap, every device mirrors (`StatusHistoryLog.remove`). Pre-cloud-log entries are local-only.
    - **Persisted dates are whole seconds** — App Group JSON is ISO-8601, which drops fractions, so a fractional `Date` never equals its stored copy. Truncate with `Date.wholeSeconds`: `updatedAt` at creation (`AppModel.statusTimestamp` → `StatusPayload.nextStamp`: strictly after the status it replaces, within `statusStampLeeway` — so two in one second don't share a stamp, and another of our devices' copy stamped a little ahead can't win the save over it) and ingestion (`payload(from:)`), and any new date in an equality/watermark check.

15. **Corrupt store files are preserved, not overwritten.** `SharedStore.decode`, `MomentIndex` and `StatusHistoryLog` move unreadable bytes to a `.corrupt` sidecar before falling back to empty; the index and the status log (its `onCorrupt` hook) then clear the change tokens so CloudKit refills them. Keep the pattern for any new file.
    - Store files decode entry by entry (`LossyArray`, in `MomentIndex.swift`): a bad entry costs only itself, and a write that skipped some keeps the bytes in `.corrupt`. Own unsent sends an older build left in the sidecar are salvaged once by the retry pass.
    - Sidecars don't outlive an unlink: `MomentIndex.clear()`/`StatusHistoryLog.clear()` remove theirs, `clearPairing` those of the keys it clears.
    - *Unreadable* isn't corrupt: a file that exists but can't be read (before first unlock, I/O) sets `readFailed`; nothing is saved over it, and `SharedStore.record`/`refreshDerived` skip pruning and derived fields (`insertReadable`/`loadReadable` return `nil`, judged under the lock). A fresh start's local clear waits for both stores. The snapshot likewise: `GroupFileStore.storedValue` tells `.unreadable` from `.absent`, and `SharedStore.mutate` then runs no body and writes nothing. So does the pairing (`SharedStore.pairingState`): unreadable is never unpaired — `refresh` throws `SyncError.storeUnreadable`, the NSE leaves CloudKit's words held for upkeep to reword, the widget draws "Unlock to see the latest" (`SharedStore.isLockedOut` → `WidgetContent.isLocked`, never the unlinked look) and comes back in 15 minutes (`WidgetReloadPolicy.whileLocked`), not an hour; `requirePairing` throws `storeUnreadable` too, never `notPaired`.
    - A kind from a newer build decodes as `Moment.Kind.unsupported(raw)`: filed under its own name, never prefetched or fetched (`ensureMedia`), shown in the library and gallery as an "Update to see this" placeholder (`UnsupportedMomentView`) that is never marked seen; its banner says to update.

16. **Publish-success flags verify currency.** `Snapshot.markStatusPublished(payload)` and `recordLogged(_:)` move `myStatusPublished`/`myStatusLoggedAt` only for the still-current status. `CloudSync.publish` never writes an older payload over `mine`; `setStatus`, the rename and `publish` take the nudge fields from the store inside the mutate; the fold never replaces an unpublished local `mine`.
    - Renames publish with `logged: false` unless the status was never logged (`myStatusLoggedAt` = the confirmed `wordsAt`; rename and `Outbox.republishStatus` log exactly when it differs). Always written — null means owed; only a missing key is the pre-field upgrade, seeded from a published `mine` at decode. Receivers log and announce renames as renames.
    - Status, nudge and anniversary saves use `.ifServerRecordUnchanged` (`.changedKeys` silently lost races); `serverRecordChanged` (bare or per-item) makes `retryingConflicts` refetch and retry — three attempts in all (the nudge counts on the conflict's own `serverRecord` instead of refetching; a cached record that's gone is fetched, never read as the zone gone).
    - `saveStatus` follows `StatusSavePolicy`: an identical server copy isn't re-saved; a newer one stamped ≤ now + `statusStampLeeway` (2 min) supersedes ours and `publish` adopts it rather than reporting success; one past that came from a clock running ahead, and ours overwrites it. A save starts from `SharedStore.statusRecordCache` (system fields + the words it held, refreshed by every save and every readable delta carrying our status record) only when the policy says `.save` on it: the change tag proves it current, and a conflict or `unknownItem` clears it and falls back to fetch-and-decide. The status log save carries the prune's first batch (non-atomic, `confirmedPrunes`).

17. **Scrub gestures need `.highPriorityGesture`** (`ScrubbableWaveform`) in the gallery pager; never wrap a waveform in a `Button` (see `VoiceMemoRow`). A plain `.gesture` loses to the horizontal paging ScrollView. In a vertical ScrollView pass `scrollSafe: true` (`HorizontalScrub`, a pan that fails on vertical movement), or the drag hijacks scrolling.

18. **Pin vertical-ScrollView content with `.containerRelativeFrame(.horizontal)`** (see `HomeView`): a child with a wide *ideal* size (a long single-line `Text`) can let the screen pan sideways; prefer `.fixedSize(horizontal: false, vertical: true)` on wrapping text. (`WaveformBars` never reports more than its width.)

19. **Never hold a shared-container file lock without a suspension guard** (suspended mid-`flock` = `0xdead10cc`). `CrossProcessLock.withLock` holds a `performExpiringActivity` assertion; paths that end a background task (`withUploadProtection`) do post-await bookkeeping *inside* the protected closure.

20. **Moderation is local and sticky (App Review 1.2).** `TermsView` gates everything until `SharedStore.acceptedTermsVersion` reaches `AppConfig.termsVersion`.
    - A reported moment goes into `hiddenMomentIDs`, filtered by `CloudSync.apply` from every delta (resyncs re-deliver it); a reported status hides by `hiddenPartnerStatusAt`. `AppModel.block` records the partner in `blockedOwnerRecordNames` *before* clearing the pairing and wipes even if the cloud unpair fails (the one place local-first is right); `acceptShare`/`discoverExistingPairing` refuse them.
    - `ContentFilter` (word-level, partner text only, every surface; names skip `nameExemptions`, words that are also ordinary names) applies *only through `Moderation.swift`'s helpers*: `StatusPayload.moderation(reportedAt:revealed:…)` → `ModeratedStatus` (reported → no words or emoji; filtered → placeholder unless revealed) and `moderated(reportedAt:)`; `StatusHistoryEntry.moderation`/`moderated`; `Moment.moderatedCaption(revealed:)` → `ModeratedText` (flags a placeholder), `displayCaption`, `displaySenderName(fallback:)`; `Snapshot.moderatedPartnerName`/`partnerName(filterEnabled:)`. Names are user text too. An unopened reveal celebration is sealed the same way: pass `sealed: snapshot.partnerStatusSealed` (`ModeratedStatus.sealed`; history rows `sealedAt:`), so its words reach no surface but `CelebrationOverlay`. The widget (`WidgetContent`) and NSE read `hiddenPartnerStatusAt` like Home; `StatusPayload.wordsShown` is the receipt-side twin.
    - Reports are `mailto:` `AppConfig.supportEmail` (24-hour response promised in the terms and on the site). Report/reveal are also `accessibilityActions` (partner card, library tiles); the celebration overlay has its own Report….

21. **No `.safeAreaInset(edge: .top)` over a scrolling list in a `NavigationStack`**: the bar tracks the scroll offset the inset adjusts, and they loop until the watchdog kills the app. `StatusHistoryView`/`MomentLibraryView` pin their filter in a plain `VStack`. Home's offline card lives *inside* its scroll content — a pinned banner above Home's `ScrollView` hung launch the same way.

22. **A save is confirmed by the record's own result, never by the call returning.** Every `modifyRecords` goes through `CloudSync.confirmSaved`/`confirmDeleted` (shares: `savedShare`) — a failed record can sit *inside* a successful result. Partial failures go through the `CKError` helpers (`itemErrors`, `isEvery(of:)`, `isAny(_:)`).
    - Recovery: after a complete full-zone fetch in the app (`previous == nil`, nothing more coming), `MomentIndex.requeueMissingUploads` re-queues own moments marked uploaded that the zone didn't return (by record *name*: unreadable copies count) if their media is on disk. Diagnostics' "Re-check sent moments" (`AppModel.resyncHistory`) clears the tokens to force one.
    - Uploads, refreshes and status/receipt/anniversary/subscription writes are bounded (`uploadDeadline`/`refreshDeadline`/`publishDeadline`): CloudKit's own timeout is seven days, and a stall held `isRetryingUploads`/`isRefreshing` until relaunch. For uploads the bound is the caller's wait; the upload runs on while it moves (`withStallWatch`). Unbounded: the app's nudge (its release lives in `CloudSync.sendNudge`) and user-driven pairing/unlink calls.
    - `SyncCoordinator` holds `isRefreshing` for the fetch only and runs the recovery pass after, outside it, each through a `RunGate` whose rule every caller names: a push or pull-to-refresh mid-fetch waits and has it run once more (`.joinAndRerun`); launch and foregrounding join the one in flight (`.join`: one fetch on cold launch); Diagnostics' resync runs only if none is (`exclusiveFetch`). Returning means a fetch covering the call landed. Each fetch starts one recovery pass (`recoveryAfterFetch`), however many callers shared it; an account change forces its own readiness look (`checkReadiness(fresh:)`). An abandoned receipt write can land late, so the next launch re-sends receipts, even when off (invariant 13). A zone-level failure only in `recordZoneFetchResultBlock` is thrown, never an empty "complete" delta.

23. **Nothing from the shared zone is trusted** — a modified build can write anything. At ingestion (`CloudSync.payload(from:)`, `moment(from:)`, `logEntry(from:)`):
    - dates go through `TrustedTime.plausible`: ≤ the server `modificationDate` + `clockSkewAllowance` (a *day*, so clocks set minutes ahead pass and keys still match), never before 1970 (ISO-8601 can't read a negative year). Receipt and request dates too; the anniversary floors at `Anniversary.earliest` (1900). A partner moment's `sentAt` is held tighter — never past the server's `creationDate` + `momentClockLeeway` (2 min, `CloudSync.trustedSentAt`): it keys nothing, and orders the history and judges news.
    - the *partner's* text is capped (`statusMessageMaxLength`, `statusEmojiMaxLength`, `displayNameMaxLength`, `captionMaxLength`; own records aren't — `payload(from:fromPartner:)`); waveforms are finite and 0…1 (a NaN made the index unsavable); nudge counts clamp to `nudgeCountCeiling`, incremented from the clamped value.
    - Stored marks over a day ahead of this phone are stale to `RefreshDelta.fold`, the status claims, `pendingCelebration` and `MomentIndex.insert`; `saveStatus` caps the server copy alike.
    - The index's cap (`momentHistoryLimit`, 5,000) never drops a pending own send, nor a favourite (`Moment.favouritedAt`, local only); `MediaRetention` keeps both's files whatever their age. A nudge breaks through Focus only when fresh, at most once per `nudgeBreakthroughInterval` (`AnnouncementPolicy.nudgeInterruption`, claimed with the nudge). `Snapshot` decodes field by field (a bad value costs that field only); `Anniversary`, `StatusSeen` and `FreshStart` decode by hand (their encoders are synthesized: same keys, optionals omitted).

24. **A fresh start clears only with both committed, each side its own records, by server time.**
    - The asker's epoch is its `FreshStart` record's server save time (never re-saved, never queued offline); the agreer names it (final); the asker's app commits on seeing it. Withdraw and commit both write the asker's record under `.ifServerRecordUnchanged`, judged against the server copy (`FreshStartPolicy.transition`), so they can't both land.
    - Then each phone's *app* clears (`Outbox.advanceFreshStart` → `CloudSync.clearHistory`): re-reads both records from the server, deletes its own moments/`StatusLog`s created (server `creationDate`) before the epoch and its receipt — never `status-*`/`nudge-*` (read as an unlink), the `FreshStart` record, or the current status's log — and only then purges its copy (`FreshStartPolicy.purge`: the zone's classification wins; an own unsent send is kept and sent). Extensions only read and fold.
    - `Snapshot.freshStart.clearedBefore` (moved only by a *published* commit, max-only) drops older moments/logs from every delta at parse time — before readability, so they don't hold the token — and from `requeueMissingUploads` (held off while a `FreshStart` record is unreadable or owed). Stores re-judge each insert *inside their locks* (`FreshStartPolicy.clearedFilter`), so a batch parsed before the commit can't re-file what was purged; the clear stands aside for the upload retry and any upload in flight, and runs again via `linkFreed` after a landing — otherwise at the next refresh's recovery pass.
    - Our own record written by another account (`lastModifiedUserRecordID`; positive proof only, and only once this phone knows its real record name, else a failed lookup wedges the clear) is never our consent.

25. **UIKit delegate callbacks with a completion run on the main actor — never `nonisolated async`.** The thunk calls the completion wherever the body finishes, and `UNUserNotificationCenterDelegate.didReceive`'s asserts the main thread. `AppDelegate` conforms `@preconcurrency` so its witnesses can be main-actor isolated despite non-`Sendable` `UNNotification`/`UNNotificationResponse`; keep new ones the same.

## CloudKit schema gotchas (full detail: README "Shipping it")

- Production auto-creates nothing; deploy after Development use. `cloudkit.share` enters the schema only when a Debug device build saves a share; `Receipt`, `StatusLog`, `Anniversary`, `AnniversaryRequest` only once one is saved (`statusSeenAt`/`statusSeenFor` once a status has been on screen; `Status.celebrationStyle` once a celebration preset is sent); `FreshStart` gets every field only from a complete two-device round.
- Field encryption is fixed at creation. Code signing picks the environment (Dev vs Prod); mixed-environment devices can't see each other — looks like a broken pairing (`CloudDiagnostics`).
- **A second device on the same iCloud account** (a Simulator signed in as you) is the same CloudKit user and `PairRole`: it writes *your* records and fires *your* subscriptions. Its writes show as your own, never the partner's; the NSE words its pushes "from another device" (invariant 10).
- Subscriptions: `status-alerts` (visible; registered silent — the NSE adds the sound), `nudge-alerts`, `moment-alerts` (visible + sound + mutable content); legacy `status-changes` is deleted on sight.
