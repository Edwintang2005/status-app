# Invariant 22: A save is confirmed by the record's own result, never by the call returning

Read before touching every `modifyRecords`, `confirmSaved`/`confirmDeleted`, deadlines, `SyncCoordinator`.

**A save is confirmed by the record's own result, never by the call returning.** Every `modifyRecords` — zone deletes and subscription saves included — goes through `CloudSync.confirmSaved`/`confirmDeleted` (shares: `savedShare`) — a failed record can sit *inside* a successful result. Partial failures go through the `CKError` helpers (`itemErrors`, `isEvery(of:)`, `isAny(_:)`).
- Recovery: after a complete full-zone fetch in the app (a sweep from no token, nothing more coming — carried across refreshes when its budget or a failed later batch cuts it short, `CloudSync.Sweep.Carry`, in memory, only while the stored token is still the one it kept), `MomentIndex.requeueMissingUploads` re-queues own moments marked uploaded that the zone didn't return (by record *name*: unreadable copies count) if their media is on disk. Diagnostics' "Re-check sent moments" (`AppModel.resyncHistory`) clears the tokens to force one.
- Uploads, refreshes and status/receipt/anniversary/subscription writes are bounded (`uploadDeadline`/`refreshDeadline`/`publishDeadline`): CloudKit's own timeout is seven days, and a stall held `isRetryingUploads`/`isRefreshing` until relaunch. For uploads the bound is the caller's wait; the upload runs on while it moves (`withStallWatch`). Unbounded: the app's nudge (its release lives in `CloudSync.sendNudge`) and user-driven pairing/unlink calls.
- `SyncCoordinator` holds `isRefreshing` for the fetch only and runs the recovery pass after, outside it, each through a `RunGate` whose rule every caller names: a push or pull-to-refresh mid-fetch waits and has it run once more (`.joinAndRerun`); launch and foregrounding join the one in flight (`.join`: one fetch on cold launch); Diagnostics' resync runs only if none is (`exclusiveFetch`). Returning means a fetch covering the call landed. Each fetch starts one recovery pass (`recoveryAfterFetch`), however many callers shared it; an account change forces its own readiness look (`checkReadiness(fresh:)`). An abandoned receipt write can land late, so the next launch re-sends receipts, even when off (invariant 13). A zone-level failure only in `recordZoneFetchResultBlock` is thrown, never an empty "complete" delta.
