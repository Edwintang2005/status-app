# Invariant 13: Read receipts are double-gated and sticky

Read before touching `CloudSync+Receipts`, `Outbox.flushReceipts`, `AppModel.markSeen`/`markPartnerStatusSeen`.

**Read receipts are double-gated and sticky.** `readReceiptsEnabled` gates publishing and display. `Snapshot.receiptsDirty` + `Outbox.flushReceipts()` is the retry loop: claimed before the call, re-set on failure, so a `markSeen` or toggle mid-flight goes next pass. A claim marks them `receiptsUnsettled`; only a confirmed write settles them, and not once a write in this process was abandoned (it can land late, over a newer one) — launch re-arms only unsettled receipts (`rearmUnsettledReceipts`). With every field set the save skips the fetch (`.changedKeys` checks no change tag); a retraction (no status receipt) fetches first, so its removals count. Writes are debounced (`scheduleReceiptFlush`, 5 s) and flushed in a background task on backgrounding (a flush already under way when the app backgrounds isn't covered: the call returns at once); the toggle and recovery pass flush at once. Off publishes an empty map and no status receipt.
- `applyPartnerReceipts` never un-sees; `MomentIndex.insert` keeps local-only fields (`seen`, `seenAt`, `seenByPartnerAt`, `uploaded`, `favouritedAt`) over re-deliveries. Receipts fold in *after* a delta's moments.
- The **status** receipt (`Snapshot.partnerStatusSeen` out, `myStatusSeenByPartner` in) is stamped only by `AppModel.markPartnerStatusSeen` from Home while `.active` with no sheet over it (`homeSheetShowing`, `rootSheetShowing`; re-stamped when the last closes), naming the status shown — a background refresh or a status under the picker isn't anyone looking. It stamps **`wordsAt`**, forward only (a rename neither re-stamps nor loses it), and only once the words are shown (`StatusPayload.wordsShown`: reported, or filtered and not revealed via `AppModel.revealPartnerStatus`, stamps nothing). It displays only while its `statusUpdatedAt` equals `mine.updatedAt` or `mine.wordsAt`.
