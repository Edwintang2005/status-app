# Invariant 16: Publish-success flags verify currency

Read before touching `Snapshot.markStatusPublished`, `CloudSync.publish`/`saveStatus`, `StatusSavePolicy`, `retryingConflicts`.

**Publish-success flags verify currency.** `Snapshot.markStatusPublished(payload)` and `recordLogged(_:)` move `myStatusPublished`/`myStatusLoggedAt` only for the still-current status. `CloudSync.publish` never writes an older payload over `mine`; `setStatus`, the rename and `publish` take the nudge fields from the store inside the mutate; the fold never replaces an unpublished local `mine`.
- Renames publish with `logged: false` unless the status was never logged (`myStatusLoggedAt` = the confirmed `wordsAt`; rename and `Outbox.republishStatus` log exactly when it differs). Always written — null means owed; only a missing key is the pre-field upgrade, seeded from a published `mine` at decode. Receivers log and announce renames as renames.
- Status, nudge and anniversary saves use `.ifServerRecordUnchanged` (`.changedKeys` silently lost races); `serverRecordChanged` (bare or per-item) makes `retryingConflicts` refetch and retry — three attempts in all (the nudge counts on the conflict's own `serverRecord` instead of refetching; a cached record that's gone is fetched, never read as the zone gone).
- `saveStatus` follows `StatusSavePolicy`: an identical server copy isn't re-saved; a newer one stamped ≤ now + `statusStampLeeway` (2 min) supersedes ours and `publish` adopts it rather than reporting success; one past that came from a clock running ahead, and ours overwrites it. A save starts from `SharedStore.statusRecordCache` (system fields + the words it held, refreshed by every save and every readable delta carrying our status record) only when the policy says `.save` on it: the change tag proves it current, and a conflict or `unknownItem` clears it and falls back to fetch-and-decide. The status log, and the prune's first batch, ride the status's own save (`LogRide`: one `modifyRecords`, non-atomic, under the status's change-tag check — a log record already there is that log, landed, since it's named by `wordsAt`; `confirmedPrunes`); only a status already saved (`alreadySaved`) or a log that didn't land gets a save of its own (`saveStatusLog`, overwriting). Accepted: non-atomic, a status attempt that conflicts still commits its log, so a retry that ends `superseded` (an overlapping publish of our own) leaves a history row for a status that never became current.
