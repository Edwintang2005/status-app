# Build, test and CI

The full notes behind [CLAUDE.md](../CLAUDE.md)'s "Build & run".

- `RedString.xcodeproj` is **generated** from `project.yml` (`make project`) but **committed** (Xcode Cloud needs it): after adding/renaming files, `make project` and commit the project too. Never edit project settings in Xcode's UI — they're overwritten. XcodeGen is pinned in `.xcodegen-version`; `make project` refuses any other version.
- `make build` is an unsigned compile check — never launch it (it traps on the App Group); other targets in README "Commands". Demo mode: `REDSTRING_DEMO=1` (Debug only) — `DemoBackend` + `DemoSeeder`, no iCloud.
- CI (`.github/workflows/ci.yml`), two parallel jobs, each uploading its `.xcresult` on failure: `test` — xcodegen drift check → unsigned Debug `build-for-testing`, warnings as errors (the simulator boots meanwhile) → unit tests (`test-without-building`) → UI tests compiled, not run; `release` — an unsigned Release build of the committed project (arm64, no dSYMs). Both Debug steps pass the same build settings, or the second rebuilds. dSYMs are Release-only (`project.yml`). Strict concurrency is `complete` (Swift 5 mode): zero warnings in every target. CI's Xcode (`^26.0`) can be older than yours and reject patterns a newer one accepts (e.g. a `@MainActor` task-group child) — a local pass isn't proof. The Pages site needs no workflow: GitHub Pages serves `main`'s `/docs` folder.
- `make test` runs `Tests/RedStringTests`, compiling `Sources/Shared/` directly (no host app, signing or App Group): the stores (Codable fallbacks, watermarks, merging, `GroupFileStore`/`CrossProcessLock` on temp directories), ingestion caps, and every pure decision type (`ParsedDelta`, `RefreshDelta`, `TokenAdvancePolicy`, `AnnouncementPolicy`, `PushBannerPolicy`, `Outbox` over `FakeBackend`, `FreshStartPolicy`, `SharePosture`, `TimelinePlan`, …), and the sequencing around them: `CloudSync.refresh`/`unpair` over `FakeCloudDatabase` (`CloudSyncSeamTests`: `CloudSync(stores:database:prefetchesMedia:)` — `CloudStores` of temp stores, no container), `SyncCoordinator` over a host recorder, `SyncRunner` over `FakeBackend`. **Keep decisions in those types:** `CloudSync.apply` performs what `ParsedDelta` decides, `AppModel` hands send loops to `Outbox` (`Outbox.testing`) and fetch timing to `SyncCoordinator`, `SyncRunner`/`NotificationService` apply `PushBannerPolicy`. Stores take an injected URL, directory or `UserDefaults` suite — **never a `.shared` singleton in a test**: the host-less bundle resolves the simulator's real App Group container and writes the installed app's data (`SharedStore`'s static locks still do, lock files only). `MomentIndex`/`StatusHistoryLog` keep their lock file beside their data file, so a test's lives in its temp directory; pass `onCorrupt: {}`, or a corrupt test file clears the real container's change tokens. `TestSupport.swift`: `Fixtures` (`zone`, `statusRecord`) and `waitUntil` — wait on conditions, never sleep.
- `make uitest SIM=...` runs `Tests/RedStringUITests`: a demo-mode smoke over Home and every main sheet (the drawing palette too), and over the screens no sheet reaches — onboarding through the invite link and the anniversary ask (`REDSTRING_DEMO_UNPAIRED=1`), Diagnostics, Fresh start, the recap, a sealed celebration (`REDSTRING_DEMO_CELEBRATION`) — each with `performAccessibilityAudit()`, a launch-hang guard (every screen must answer a query in time; invariants 18, 21) and `assertFitsScreen` (nothing hangs past the window's sides); a pass at the largest accessibility text size; and one test that opens each sheet on its first tap, no retries. `make uitest-narrow` runs it on the 375 pt iPhone SE (3rd generation). Signed, so CI only compiles it. The audit lists elements hidden from VoiceOver too (under a cover, under the scratch card's foil): `audit(_:within:)` judges a cover's own elements. Exclusions (`DemoSmokeTests.accepts`: Dynamic Type wholesale — `Theme.rounded` doesn't follow a live size change, on ROADMAP — system chrome (the keyboard and its suggestion bar, the date picker), disabled controls, emoji, misreads measured from the run's own recording) stay narrow and commented. Not covered: the easter egg (reached only from a milestone reminder) and the share sheet (another app's).
- User-facing text: `Text` literals, `String(localized:)` elsewhere; each target's `Resources/Localizable.xcstrings` is filled by an Xcode IDE build (xcodebuild leaves it empty — harmless). Icon-only controls carry an `accessibilityLabel`; `Theme.rounded` follows Dynamic Type (capped at 1.35×).
